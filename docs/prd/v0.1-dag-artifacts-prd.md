# 0.1：基于 DAG 的群聊工件助手

## Summary

0.1 面向群聊协作：用户向助手提出需求，模型使用本地容器生成文件，Runtime 收集工件并直接上传为来源群的群文件，同时将执行结果和工件引用提交到 DAG。后续对话从 DAG 获取已完成结果，群之间严格隔离。版本以这条产品链路的可执行与可恢复为验收目标。

## Motivation

立项时消息、Agent 工具循环和 SQLite 已具备运行基础，但 ContextGraph 尚未参与实际对话，也没有本地容器执行与群文件交付能力。仅有文本回复不能闭环报告、表格、图片等文件生成请求。本版本已补齐这条链路，验收情况见闭环状态文档。

## Goals

- 群聊触发 → DAG 上下文 → 容器工作 → 工件收集 → 群文件上传 → 群聊结果回复
- 工具参数不能选择宿主命令、挂载目录、容器镜像或目标群
- 已完成结果可追溯，重复投递不重复执行已确认的外部动作，结果不确定时明确停止自动重放
- 每个实现阶段通过完整验收后独立提交

## Non-Goals

- 代码仓库编辑、Git/PR、IDE 和通用 code agent 工作流
- 通用 Workflow 编排、定时主动任务、多 Agent 调度和向量检索
- 任意宿主执行、特权容器、宿主 Docker socket 挂载和用户指定镜像
- QQ 官方接口不具备的群文件上传能力，不用文本链接伪装群文件成功
- 未经验证的历史 DAG 表自动转换和跨群历史共享

## User Experience

群成员通过现有 mention、reply 或配置的触发规则提出“生成报告并发到群文件”。模型通过容器工具生成工件，使用工件 ID 上传，随后报告实际生成和上传的结果。文件路径与群目标由 Runtime 绑定，模型不能通过参数改写目标群。

## Behavior

1. 每次被接受的对话运行拥有独立 Run Ref，从当前对话 Ref 派生
2. 容器与上传的终态结果提交到 Run Ref，结果回流时显式依赖当前对话头与 Run 结果，保留并发产生的两条历史
3. DAG 作用域由真实 Session 决定，不能由模型提供；上下文读取有预算，不注入原始容器脚本或完整工具日志
4. 容器工具仅在部署显式启用和权限允许时可调用，默认无网络，限制时间、内存、进程数、日志与工件大小
5. 每次容器调用使用独立工作目录，只收集声明的普通文件，拒绝绝对路径、目录穿越、符号链接和超限工件
6. 群文件上传仅允许当前运行产生或当前会话可访问的已登记工件，通过适配器传输内容而非假设 NapCat 能读取 Runtime 的宿主路径
7. 上传已确认成功才返回成功；超时或崩溃后未知状态不自动重复上传
8. 错误、清理与恢复行为必须可验证，不能为满足验收削弱现有测试

## Scope

纳入已有频道与触发、模型和工具循环、DAG 运行接入、本地 Docker 工件工作、NapCat 群文件上传、配置示例与恢复测试。TaskRunner 的通用任务创建入口、权限审批与平台额外动作留待后续版本；本版本的任务入口就是被触发的群聊请求。

## Compatibility

保留现有配置和文本对话，容器执行默认关闭。生产 SQLite Runtime 使用已有 ContextGraph 表，不迁移旧 ConversationNode 为 Commit，旧 Line 事件继续承担消息和外部动作回执。测试或嵌入式调用未提供 ContextGraph 时保留原有行为。

## Edge Cases

| 场景                      | 预期结果                              |
| ------------------------- | ------------------------------------- |
| Docker 不可用或镜像未安装 | 返回工具失败，不执行宿主回退          |
| 超时、日志超限或输出越界  | 终止并清理容器，拒绝收集非法工件      |
| 群不支持文件上传          | 明确报告能力不足                      |
| 跨群工件 ID 或伪造目标    | 拒绝访问                              |
| 并发群消息完成顺序相反    | 显式合并各自 Run 结果，不覆盖已有历史 |
| 已完成工具调用重放        | 返回持久化结果，不重复执行            |
| 工具调用开始后进程崩溃    | 标记结果不确定，不自动重放副作用      |

## Acceptance Criteria

- 群聊请求通过真实 Runtime/Agent/ToolRuntime 路径生成工件并调用群文件上传
- DAG 能追溯输入、容器结果、工件、上传回执和最终回复，后续对话能够读取历史结果
- 隔离、超时、失败、重放和并发回流有自动化验证
- `pnpm verify` 全部通过，容器及真实平台联调结果分别记录，不把替身测试写成真实联调

## Decisions

### 2026-10-11 — 实现验收

完整质量检查、283 项包级测试、3 项进程集成测试和真实 Docker 工件验收通过。生产装配已验证生成、上传协议、DAG 回流和重启去重；外部模型与真实 QQ 群账号尚未联调。完成状态表示本版本实现及自动化验收完成，不表示已发布或完成目标环境上线。

### 2026-10-11 — 版本定位与工件交付

用户确定 0.1 为基于 DAG 的群聊 Agent Runtime，采用容器生成工件并直接上传群文件的模式，暂不采用 code agent 范式。

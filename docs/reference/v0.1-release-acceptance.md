## 执行与证据规则

每次候选发布记录 Git SHA、版本/构建校验值、操作系统、Node/pnpm/Docker/镜像版本、配置的脱敏摘要、执行时间、执行者与复核者。证据中的 `runId`、`sourceEventId`、Session、工件 SHA-256 与平台回执必须能够相互关联。

以下用例默认均为“待执行”，运行后登记通过/失败/阻断和证据路径。没有测试环境或凭据时标记阻断，不以跳过视为通过。任何阻断功能、安全边界、数据一致性或交付真实性的问题都阻断正式发布。

## 四类验证必须分别通过

| 验证类别          | 执行方式                                                                                                                                           | 不能证明的内容                           |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 自动化与受控替身  | `pnpm verify`；新增 Run/迁移/API/SSE/恢复用例；浏览器自动化纳入 CI                                                                                 | 真实模型输出质量和平台最终文件可见性     |
| 真实 Docker       | `pnpm container:smoke`；构建 `deploy/artifacts`；`node tools/artifact-formats-smoke.mjs`；启用 `SYNAPSE_TEST_DOCKER=1` 执行 runtime-artifacts 测试 | 真实 QQ 平台已接收文件                   |
| 真实模型与 NapCat | 在指定验收群人工发起请求；核对模型、平台、下载文件和 Run                                                                                           | 不同平台/不同模型组合均兼容              |
| 浏览器与产品流程  | 真实 Admin 服务配合浏览器验收；刷新、断网、重启、错误与下载                                                                                        | 未参与测试的浏览器、负载和部署环境均可用 |

真实外部消息和上传仅在维护者明确授权的验收环境进行。每次记录成功、失败和不确定场景，区分故障注入与平台实际故障。

## 容量与持续运行基线

以下是候选版本必须测量的验收目标，尚无实测结论。测试机至少 4 vCPU、8 GiB RAM、本地 SSD；记录实际硬件与操作系统。通过前不能写成产品性能承诺。

| 项目     | 0.1 候选门槛                                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------------------------ |
| 历史量   | 10,000 个 Run、1,000,000 条有界事件；列表默认 50 条，最大 200 条，详情按页取数                                           |
| 查询     | 上述数据集本机 API 列表及首屏事件查询 p95 ≤ 500 ms，不含模型与平台耗时；记录样本数量及冷/热缓存                          |
| 实时性   | 事件落盘到本机页面可见 p95 ≤ 2 s；10 个 SSE 客户端下不漏事件                                                             |
| 断线恢复 | 断开 60 s 后可补齐期间事件，最终顺序/数量与持久查询一致                                                                  |
| 持续运行 | 候选版本连续运行 24 h，至少 100 个受控任务，包含失败与重启；无重复副作用、无未解释卡住的 Run、无持续增长的连接或容器残留 |
| 配置边界 | 对并发、排队、deadline、载荷与磁盘限制分别验证正常边界和超限行为；实际默认值在 PR-04/08 固化                             |

外部服务延迟单独统计，不能归因于 Runtime，也不能从 Runtime 指标中隐去。若目标不满足，应优化或重新评审支持规模并修改版本范围，不静默删除失败测试。

# 0.1 实施与验证记录

更新日期：2026-10-26。代码验证基线为 `86e2c5b`，本记录是开发进度，不是正式版放行结论。范围继续以[正式版 PRD](../prd/v0.1-release-prd.md)和[发布验收](./v0.1-release-acceptance.md)为准。

## 本轮四项优先工作

| 工作                                  | 已实现行为                                                                                | 验证依据                                                                     |
| ------------------------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 统一 Docker Artifact 与 ArtifactStore | 生产 `docker.run` 与 `container.run` 共用 UUID、内容摘要、会话归属、存储配额及群文件回执  | `unified-artifacts.test.ts`、原 Docker/群工件回归测试                        |
| 业务事件去除内嵌 Base64               | Docker 返回后先入库；工具、Agent 输出、回复、DAG、Trace 使用引用，实际发送前读取文件      | 检查生产运行的事件、模型请求和关闭后的 SQLite 字节，未包含附件 Base64        |
| 最终产物选择、废弃与去重              | 选择记录原子替换；同轮同名同内容复用 ID；同名修订版替换旧版；过滤未选中和重复引用         | `selection.test.ts`、`artifact-selection.test.ts`、`final-artifacts.test.ts` |
| 统一生成与交付状态                    | `generated`/`selected`/`discarded` 不表示交付；逐文件保存平台回执；回复失败不掩盖上传成功 | `final-artifacts.test.ts`、`outcome.test.ts`、回执恢复测试                   |

明确失败的草稿被废弃后，不阻碍最终文件成功交付；结果未知的上传保持 `uncertain`，不能通过废弃、换选择或再次生成绕过核对。最终集合为空是明确的不交付附件选择，不会伪造任何上传成功事实。

新生产链路不再写入文件 Base64；本轮没有重写历史数据库，旧记录中的内嵌数据仍需后续离线迁移处理。独立 `tool-execution` 的旧返回格式保留兼容，生产装配在持久化观察之前将其转换为工件引用。私聊文件和图片目前仍依赖消息整体回执，逐文件上传回执能力面向 NapCat 群文件。

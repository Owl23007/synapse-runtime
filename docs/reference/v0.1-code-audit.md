# 0.1 正式版代码审计

审计日期：2026-10-25。代码基线：`35b0c54`。本记录是实现范围核对，不是全面安全审计或正式发布认证。

## 审计结论

当前仓库具备群聊工件助手的主要执行底座，适合增量建设可观测产品。新增正式版计划的主要缺口集中在统一 Run 身份与持久 Trace、细粒度模型采集、查询与可靠 SSE、WebUI、数据维护及发布证据。原 PRD 的完成状态可以保留为基础能力记录，但不能代表新正式版完成。

状态含义：“已有”表示找到生产实现及相应测试入口；“部分”表示基础存在但尚不能满足新范围；“缺少”表示未找到目标实现。历史验收、当前复验和真实平台验收分别记录。

## 需要先解决的设计边界

1. **身份与状态**：由 Runtime 管理逻辑 Run，Agent 返回结果不能重新决定逻辑身份。恢复、命令、失败与普通执行遵循同一套状态定义
2. **持久化一致性**：Trace 是执行观察与查询入口；已存在的规范化事件、外部动作回执和 DAG 各有职责。必须说明事实源与补齐顺序，不能双写后假设不会崩溃
3. **业务成功与传输成功**：工具函数成功返回、模型输出一句“完成”、发送失败提示成功都不等于用户任务成功。工件上传与最终回复的事实分别保留
4. **实时与历史**：Run 内序号只适用于单 Run，跨 Run 订阅需要持久全局游标。内存日志可继续用于调试，不用其重建运行事实
5. **契约与依赖**：浏览器不读取 SQLite，不导入 Runtime 实现；新 DTO 与协议版本需契约测试，架构检查覆盖 TSX
6. **历史兼容**：不迁移或改写旧语义图来伪造追踪；没有记录过的输入输出显示不可用，升级前备份工件和文件回执

# 测试约定

测试放在所属包的 `tests` 目录，生产代码不引用测试夹具

- `unit`：纯逻辑或使用受控替身，不依赖真实数据库、文件读写、网络监听或外部进程
- `integration`：验证真实 SQLite、文件系统、HTTP 服务或多个生产组件之间的协作，外部模型与平台可以使用替身
- `contracts`：同一行为契约的共享注册函数，由对应层的测试调用
- 根目录 `tests/e2e`：通过构建后的入口启动真实进程，验证端到端行为

同一文件混有两类依赖时优先按行为拆分；共享同一协作场景的测试归入集成测试。分类依据测试实际使用的依赖，不依据被测源码所在目录

测试名称使用中文行为描述，可以保留 API、协议名和参数占位符，不使用“测试：”前缀。辅助构造函数使用 `create…Fixture`，调用结果使用具体领域名称或 `testContext`，避免 `f`、`setup` 等含糊命名

取得资源后立即通过 Vitest `onTestFinished` 登记释放，后取得的资源先释放，例如先停止 Runtime 或服务、再关闭数据库、最后移除临时目录。夹具负责自身创建的资源，初始化中途失败也应释放。不要使用跨用例的全局资源数组

需要验证关闭、重启或租约释放时，在断言所需时点显式释放；局部作用域的 `try/finally` 可表达该生命周期边界。结束钩子作为异常路径的兜底，重复释放须符合资源自身的幂等契约

只提炼反复出现且含义稳定的输入或资源夹具，保留与当前行为相关的配置、替身和断言。通过公共行为验证结果，避免冻结完整导出列表、内部目录或构造字段，从而允许 Runtime 自由演进

本地 `pnpm verify` 与 CI 均执行 `pnpm typecheck:tests`；端到端测试运行前先构建工作区
